# Canonical Data Schema — `TripState` Specification

- **Contract Version:** `1.0.0`
- **JSON Schema Dialect:** Draft 2020-12
- **Schema URI:** `https://agentic-travel-planner.local/contracts/trip-state/1.0.0`
- **Machine-Readable Source:** [`docs/json/schemas/trip-state.schema.json`](file:///Users/krishay/projects/tourism/docs/json/schemas/trip-state.schema.json)

---

## 📌 Overview

The `TripState` schema is the single canonical interchange object for the Agentic Travel Planner. Every planning run operates by transforming and enriching an instance of `TripState`. 

Agents mutate `TripState` via `AgentPatch` operations according to strict path ownership rules, and every published itinerary snapshot becomes an immutable versioned record.

## 🧩 Type Definitions (`$defs`)

### Core Primitives

#### `Money`
- **Properties:**
  - `amount` (Number ≥ 0, Required)
  - `currency` (String, ISO 4217 3-letter code, e.g., `"INR"`, `"USD"`, Required)

#### `DataFact`
- **Properties:**
  - `source` (String, Required): Source of fact.
  - `observed_at` (Timestamp RFC 3339, Required)
  - `fresh_until` (Timestamp RFC 3339, Required)
  - `confidence` (Number `0..1`, Required)
  - `cached` (Boolean, default `false`)

#### `ScoreComponents`
Detailed multi-dimensional evaluation score components (`0..100` each, except `overall_score` `-500..400`):

| Field | Type | Range | Description |
|---|---|---|---|
| `preference_fit` | Score | 0..100 | Alignment with traveler profile preferences |
| `experience_quality` | Score | 0..100 | Curated quality rating of experiences |
| `comfort` | Score | 0..100 | Accommodation & transit comfort rating |
| `authenticity` | Score | 0..100 | Local cultural authenticity score |
| `fatigue` | Score | 0..100 | Physical exertion penalty |
| `cost_penalty` | Score | 0..100 | Proximity to budget ceiling penalty |
| `logistics_penalty` | Score | 0..100 | Transfer frequency and transit overhead |
| `regret_risk` | Score | 0..100 | Weather and availability risk penalty |
| `disruption_penalty` | Score | 0..100 | Disruption penalty vs parent version (0 on initial run) |
| `overall_score` | Number | -500..400 | Final composite score used for candidate ranking |

### Candidate Itinerary & Evaluation

#### `CandidateItinerary`
- **Properties:**
  - `candidate_id` (Id, Required)
  - `branch` (Enum: `"initial"`, `"minimal_change"`, `"full_reoptimization"`, `"alternative"`, Required)
  - `rank` (Integer `1..3`, Optional): Deterministic rank after optimization.
  - `feasible` (Boolean, Required): `true` if all hard constraints pass.
  - `hard_constraint_failures` (Array<`Failure`>, Required): List of violated hard gates if infeasible.
  - `mobility` (Object): `{ feasible: boolean, transit_minutes: int, transfer_count: int }`
  - `cost` (Object): `{ total: Money, within_budget: boolean, substitutions: string[] }`
  - `local_advice` (Array<String>): Advisory notices from Local Intelligence Agent.
  - `total_cost` (`Money`): Aggregated total cost.
  - `score_components` (`ScoreComponents`, Required)
  - `confidence` (Number `0..1`, Required)
  - `assumptions` (Array<String>)
  - `tradeoffs` (Array<String>)
  - `itinerary` (`Itinerary`)
  - `simulation` (`SimulationResult`)

### Workflow & Communication Types

#### `PlanningRun`
- **Properties:**
  - `run_id` (Id, Required)
  - `status` (Enum: `"queued"`, `"running"`, `"awaiting_user_decision"`, `"completed"`, `"failed"`, Required)
  - `started_at` (Timestamp RFC 3339, Required)
  - `unanswered_questions` (Array<String>): Questions requiring traveler discovery answers.
  - `constraint_report` (Array<String>): Infeasibility report lines.
  - `relaxation_options` (Array<Object>): Available relaxation options for traveler decision.
  - `error` (`Failure`): Terminal failure details if failed.

#### `AgentPatch`
JSON Patch structure used by agents to communicate state modifications:
- **Properties:**
  - `agent_id` (Integer `1..10`, Required): Numeric agent identifier.
  - `operations` (Array<Object>, Required): Array of standard JSON Patch ops (`add`, `replace`, `remove`, `test`) with `path` and `value`.

#### `PlanningEvent`
- **Properties:**
  - `event_id` (Id, Required)
  - `type` (Enum, Required): `trip.created`, `discovery.updated`, `planning.started`, `agent.completed`, `planning.awaiting_user_decision`, `itinerary.published`, `replan.requested`, `planning.failed`.
  - `occurred_at` (Timestamp RFC 3339, Required)
  - `trip_id` (Id, Required)
  - `run_id` (Id, Required)
  - `version` (Integer ≥ 1, Required)
  - `payload` (Object)

#### `ReplanningRequest`
- **Properties:**
  - `request_id` (Id, Required)
  - `type` (Enum, Required): `weather`, `closure`, `budget_change`, `duration_change`, `fatigue`, `delay`, `preference_change`, `party_change`.
  - `occurred_at` (Timestamp RFC 3339, Required)
  - `description` (String, Required)
  - `affected_activity_ids` (Array<Id>)

## 🔒 Validation Rules & Constraints

1. **`additionalProperties: false`**: Enforced on all objects to prevent schema pollution or unvetted fields.
2. **Timestamps**: Must be valid RFC 3339 strings matching regex `(Z|[+-][0-9]{2}:[0-9]{2})$` (explicit timezone offset required).
3. **Currencies**: ISO 4217 3-letter uppercase codes matching `^[A-Z]{3}$`.
4. **Candidate Constraint**: Maximum of 3 evaluated candidates per planning run.
